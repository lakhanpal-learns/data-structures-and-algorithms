# 209. Minimum Size Subarray Sum

**LeetCode:** https://leetcode.com/problems/minimum-size-subarray-sum/  
**Pattern:** Sliding Window  
**Difficulty:** Medium

## 1. Problem Statement

Given an array of **positive integers** `nums` and a positive integer `target`, return the minimum length of a contiguous subarray whose sum is greater than or equal to `target`. If no such subarray exists, return `0`.

A subarray must contain consecutive elements.

## 2. Example

```text
target = 7
nums = [2, 3, 1, 2, 4, 3]
Output = 2
```

The subarray `[4, 3]` sums to `7` and has length `2`.

## 3. How We Discover the Optimized Solution

The goal is to understand why sliding window works, not just memorize the code.

### Observation 1: Start with brute force

Choose every starting index, extend the subarray to the right, and keep a running sum. Whenever the sum reaches the target, record the length and keep the minimum.

This works, but can take **O(n²)** time because many overlapping subarrays are checked.

Ask: **Can we reuse the sum we already have instead of recalculating it?**

### Observation 2: The numbers are positive

This is the key property:

- Adding an element on the right increases the window sum.
- Removing an element on the left decreases the window sum.

So we can grow the window until it becomes valid, then shrink it to look for a shorter valid window. This leads to the **sliding-window pattern**.

> This reasoning relies on positive numbers. The same simple window rule does not generally work when negative numbers are allowed.

### Observation 3: Keep track of one window

Maintain:

- `left`: the start index of the current window.
- `right`: the end index of the current window.
- `sum`: the sum of elements between `left` and `right`.
- `minLength`: the shortest valid length found so far.

When moving `right), add the new element to `sum`. When the sum reaches the target, record the length and try moving `left` forward.

### Observation 4: Why do we use `while`, not `if`?

A single expansion can produce several valid windows. We must keep shrinking as long as the current window remains valid.

For target `7`, consider `[3, 1, 2, 4]`:

1. Its sum is `10`, length `4`.
2. Remove `3`: `[1, 2, 4]`, sum `7`, length `3`. Still valid.
3. Remove `1`: `[2, 4]`, sum `6`. Now invalid.

An `if` shrinks only once; a `while` checks again after each removal and finds the shortest valid window ending at the current right index.

### Observation 5: Why initialize `minLength` to `nums.size() + 1`?

The longest possible subarray has length `nums.size()`. Therefore, `nums.size() + 1` is larger than every possible answer and acts as a sentinel meaning **no valid window has been found yet**.

If it still has that value at the end, return `0`. Otherwise, return the minimum length.

## 4. Complete C++ Solution

```cpp
#include <vector>
#include <algorithm>
using namespace std;

class Solution {
public:
    int minSubArrayLen(int target, vector<int>& nums) {
        int left = 0;
        int sum = 0;
        int minLength = nums.size() + 1;

        for (int right = 0; right < nums.size(); right++) {
            sum += nums[right];

            while (sum >= target) {
                minLength = min(minLength, right - left + 1);

                sum -= nums[left];
                left++;
            }
        }

        if (minLength == nums.size() + 1) {
            return 0;
        }

        return minLength;
    }
};
```

## 5. Why `right - left + 1`?

Both endpoints are included in the window. For example, if `left = 2` and `right = 5`, the included indices are `2, 3, 4, 5`—four elements.

```cpp
right - left + 1  // 5 - 2 + 1 = 4
```

Subtracting only `right - left` gives the distance between the indices, not the number of included elements.

**Rule:** for an inclusive index range, length = `right - left + 1`.

## 6. Dry Run

Input: `target = 7`, `nums = [2, 3, 1, 2, 4, 3]`

| Action | Current sum | Window / result |
|---|---:|---|
| Add `2` | 2 | Invalid |
| Add `3` | 5 | Invalid |
| Add `1` | 6 | Invalid |
| Add `2` | 8 | `[2,3,1,2]`, length 4; remove `2`, sum becomes 6 |
| Add `4` | 10 | `[3,1,2,4]`, length 4; remove `3`, sum becomes 7 |
| Shrink again | 7 | `[1,2,4]`, length 3; remove `1`, sum becomes 6 |
| Add `3` | 9 | `[2,4,3]`, length 3; remove `2`, sum becomes 7 |
| Shrink again | 7 | `[4,3]`, length 2; remove `4`, sum becomes 3 |

The shortest valid window has length **2**, so the answer is `2`.

## 7. Understanding the Final Return

```cpp
if (minLength == nums.size() + 1) {
    return 0;
}
return minLength;
```

- If `minLength` never changed from its sentinel value, no valid subarray was found.
- Otherwise, it contains the smallest valid length discovered.

## 8. Complexity

- **Time: O(n).** The `right` pointer visits each element once, and `left` only moves forward. Across the whole algorithm, each pointer advances at most `n` times.
- **Auxiliary space: O(1).** Only a few integer variables are used.

## 9. Common Mistakes

1. **Using `if` instead of `while`:** may stop shrinking before finding the minimum length.
2. **Using `right - left`:** forgets that both endpoints are included.
3. **Returning the first valid length:** a later window may be shorter.
4. **Forgetting the no-answer case:** return `0` if the sentinel remains unchanged.
5. **Using the same rule with negative numbers:** removing an element no longer guarantees the expected behavior.

## 10. Algorithm-Discovery Checklist

When you meet a new subarray problem, ask:

1. What is the brute-force approach?
2. What property of the input lets us move pointers safely?
3. Can we update a running sum instead of recalculating it?
4. Once the window is valid, can shrinking improve the answer?
5. Do we need to shrink once or repeatedly while the condition stays true?
6. What sentinel can represent “no answer found”?
7. Can each pointer move only forward, giving linear time?

**Memory phrase:** Expand → Check → Record → Shrink while valid.
