# 287. Find the Duplicate Number

**Difficulty:** Medium  
**Pattern:** Floyd's Cycle Detection (Slow and Fast Pointers)

## Problem

Given an integer array `nums` containing `n + 1` integers where every integer is in the range `[1, n]`, return the number that appears more than once.

Rules:
- Do not modify the array.
- Use only `O(1)` extra space.
- The answer is one duplicated number.

### Example

```text
Input:  nums = [1,3,4,2,2]
Output: 2
```

## Key idea

Treat each value as the index we visit next. For example, at index `0`, the value is `1`, so we visit index `1`.

Because one number is duplicated, two positions point toward the same next index. This creates a cycle. The duplicate is the entrance to that cycle.

## C++ solution

```cpp
class Solution {
public:
    int findDuplicate(vector<int>& nums) {
        // Phase 1: Find a meeting point inside the cycle
        int slow = nums[0];
        int fast = nums[0];

        do {
            slow = nums[slow];          // One step
            fast = nums[nums[fast]];    // Two steps
        } while (slow != fast);

        // Phase 2: Find the entrance to the cycle
        slow = nums[0];

        while (slow != fast) {
            slow = nums[slow];  // One step
            fast = nums[fast];  // One step
        }

        return slow;
    }
};
```

## How it works

### Phase 1 — Detect the cycle

- `slow` moves one step each iteration.
- `fast` moves two steps each iteration.
- When they meet, a cycle has been detected. This meeting point is not necessarily the duplicate.

### Phase 2 — Find the duplicate

- Reset `slow` to `nums[0]`.
- Leave `fast` at the Phase 1 meeting point.
- Move both pointers one step at a time.
- Their next meeting point is the cycle entrance, which is the duplicate.

**Simple reason:** The distance from the start to the cycle entrance matches the distance from the Phase 1 meeting point to that entrance when travelling forward around the cycle (possibly including a full extra lap).

## Dry run

Input: `[1,3,4,2,2]`

### Phase 1

Start: `slow = nums[0] = 1`, `fast = nums[0] = 1`.

| Iteration | Slow calculation | Slow | Fast calculation | Fast |
|---:|---|---:|---|---:|
| Start | `nums[0]` | 1 | `nums[0]` | 1 |
| 1 | `nums[1]` | 3 | `nums[nums[1]] = nums[3]` | 2 |
| 2 | `nums[3]` | 2 | `nums[nums[2]] = nums[4]` | 2 |

They meet at `2`, so the cycle is detected.

### Phase 2

Reset `slow = nums[0] = 1`. Keep `fast = 2`.

| Step | Slow calculation | Slow | Fast calculation | Fast |
|---|---|---:|---|---:|
| Start | Reset | 1 | Keep meeting point | 2 |
| 1 | `nums[1]` | 3 | `nums[2]` | 4 |
| 2 | `nums[3]` | 2 | `nums[4]` | 2 |

They meet at `2`. Return `2`.

## Complexity

- **Time:** `O(n)`
- **Extra space:** `O(1)`
- The input array is not modified.

## Important details

- Use a `do-while` loop in Phase 1 so the pointers move before the equality check.
- In Phase 2, both pointers move one step.
- Do not return the Phase 1 meeting value immediately; Phase 2 finds the duplicate reliably.
