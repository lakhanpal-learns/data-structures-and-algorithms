# 560. Subarray Sum Equals K

## 1. Problem Statement

Given an integer array `nums` and an integer `k`, return the total number of continuous, non-empty subarrays whose sum equals `k`.

A subarray must contain consecutive elements.

## 2. Example and Expected Output

**Input**
```text
nums = [1, 2, 1, 2], k = 3
```

**Output**
```text
3
```

The valid subarrays are:

- `[1, 2]` at indices 0–1
- `[2, 1]` at indices 1–2
- `[1, 2]` at indices 2–3

There are three valid subarrays.

## 3. C++ Solution

```cpp
#include <vector>
#include <unordered_map>
using namespace std;

class Solution {
public:
    int subarraySum(vector<int>& nums, int k) {
        unordered_map<int, int> mp;

        int sum = 0;
        int count = 0;

        mp[0] = 1;

        for (int num : nums) {
            sum += num;

            int needed = sum - k;

            count += mp[needed];

            mp[sum]++;
        }

        return count;
    }
};
```

## 4. Code Explanation — Line by Line

| Code | Purpose |
|---|---|
| `unordered_map<int, int> mp;` | Stores each prefix sum as a key and how many times it has appeared as the value. |
| `int sum = 0;` | Running sum of all numbers processed so far. |
| `int count = 0;` | Total number of valid subarrays found so far. |
| `mp[0] = 1;` | Records the empty prefix with sum 0, so subarrays beginning at index 0 can be counted. |
| `sum += num;` | Adds the current number to the running sum. |
| `int needed = sum - k;` | Calculates the earlier prefix sum that would make the subarray sum equal to `k`. |
| `count += mp[needed];` | Adds the frequency of that earlier prefix sum. Each occurrence gives a different valid starting position. |
| `mp[sum]++;` | Records the current prefix sum for future elements. |
| `return count;` | Returns the total number of valid subarrays. |

## 5. Brute-Force Approach — Where We Start

Before choosing an optimized technique, begin with the direct solution:

1. Choose every possible starting index.
2. Extend the subarray one element at a time.
3. Keep a running sum for that start.
4. Whenever the sum equals `k`, increase the answer.

This works, but it may take **O(n²)** time because there are many possible subarrays.

The question to ask next is: **Can we reuse information instead of repeatedly calculating sums?**

That question leads us toward prefix sums.

## 6. How We Discover the Optimized Solution

This section explains how to reason our way to the algorithm instead of memorizing it.

### Observation 1: We are counting continuous subarrays

A subarray is a continuous range. We need to count every range whose sum equals `k`.

Trying all ranges is a valid starting point, but we want to avoid repeatedly adding the same elements.

### Observation 2: Reuse running sums with prefix sums

Let a prefix sum be the sum of all elements from the start of the array through the current position.

For `nums = [1, 2, 1, 2]`:

| Index | Number | Prefix sum |
|---:|---:|---:|
| 0 | 1 | 1 |
| 1 | 2 | 3 |
| 2 | 1 | 4 |
| 3 | 2 | 6 |

The sum of a subarray can be found by subtracting the prefix sum before its start from the current prefix sum. This avoids adding the whole subarray again.

### Observation 3: Turn the target condition into a value we can search for

Let the current prefix sum be `sum`, and let an earlier prefix sum be `previous`.

The subarray between them has sum:

```text
sum - previous
```

We want that to equal `k`:

```text
sum - previous = k
previous = sum - k
```

So, at each position, we know exactly which earlier prefix sum we need:

```cpp
int needed = sum - k;
```

**Key discovery:** Instead of testing every earlier starting position, look for the earlier prefix sum equal to `sum - k`.

### Observation 4: Why a hashmap?

We need to find the required earlier prefix sum quickly. A hashmap lets us look up a prefix sum by its value.

But the problem asks us to **count all valid subarrays**, not just determine whether one exists. That leads to the next observation.

## 7. Why We Store Frequency — The Key Insight

This is the crucial reasoning step.

Consider:

```text
nums = [1, 0, 1], k = 1
```

The prefix sums, including the empty prefix, are:

| Position | Prefix sum |
|---|---:|
| Before the array | 0 |
| Index 0 | 1 |
| Index 1 | 1 |
| Index 2 | 2 |

When we reach the final number:

- Current prefix sum = `2`
- Target `k = 1`
- Required earlier prefix sum = `2 - 1 = 1`

The earlier prefix sum `1` appeared at two different positions. Each occurrence gives a different valid subarray ending at the current position:

- Starting after the first prefix sum `1`: subarray `[0, 1]`
- Starting after the second prefix sum `1`: subarray `[1]`

Both have sum `1`. Therefore, there are **two** valid subarrays ending at the current position.

If we stored only whether prefix sum `1` exists, we'd know there is a match but would count only one subarray. We'd miss the other one.

### How do we decide that frequency is necessary?

Follow the wording and logic of the problem:

1. We must **count** every valid subarray.
2. Each earlier position with the required prefix sum produces one valid subarray ending at the current position.
3. Therefore, we need to know **how many earlier positions** have that prefix sum.
4. The number of times a prefix sum has appeared is its **frequency**.
5. Store each prefix sum as a hashmap key and its frequency as the value.

For example, `mp[1] = 2` means prefix sum `1` has appeared twice. If `1` is the required sum, add `2` to the answer.

This is why we write:

```cpp
count += mp[needed];
```

We add the frequency because each occurrence corresponds to a different valid subarray.

**General problem-solving clue:** If a problem asks you to count all matches, ask whether one value can match at multiple earlier positions. If every occurrence creates a distinct answer, you need to account for the frequency—not merely whether the value exists.

## 8. Complete Logic in Plain English

1. Create a hashmap to remember prefix sums and how often each one has appeared.
2. Set the running sum and answer count to zero.
3. Put `mp[0] = 1` in the map. This represents the empty prefix before the array starts.
4. Visit each number from left to right and add it to the running sum.
5. Calculate `needed = sum - k`. This is the earlier prefix sum required for a subarray ending at the current position to have sum `k`.
6. Look up `mp[needed]`. Its value tells us how many earlier positions can start a valid subarray ending here.
7. Add that frequency to the answer.
8. Increase the frequency of the current running sum with `mp[sum]++`, so later positions can use it.
9. After processing all numbers, return the answer.

**Memory phrase: Update → Find needed sum → Count its frequency → Remember current sum.**

## 9. Dry Run — Step by Step

Input: `nums = [1, 2, 1, 2]`, `k = 3`

Start with `mp = {0: 1}`, `sum = 0`, and `count = 0`.

| Number | Running sum | Needed (`sum - k`) | Frequency found | Count after lookup |
|---:|---:|---:|---:|---:|
| 1 | 1 | -2 | 0 | 0 |
| 2 | 3 | 0 | 1 | 1 |
| 1 | 4 | 1 | 1 | 2 |
| 2 | 6 | 3 | 1 | 3 |

After each lookup, we increase the frequency of the current running sum.

Final answer: `3`.

## 10. Why `mp[0] = 1` Is Necessary

`mp[0] = 1` means that before processing any elements, an empty prefix with sum zero has occurred once. It does **not** mean the array contains a zero.

Example: `nums = [3]`, `k = 3`.

- After reading `3`, the running sum is `3`.
- The required earlier sum is `3 - 3 = 0`.
- `mp[0] = 1`, so we count the subarray `[3]`.

Without the initial entry, a subarray that starts at index 0 could be missed.

## 11. Why We Check Before Updating the Map

The order inside the loop is important:

```cpp
sum += num;
int needed = sum - k;
count += mp[needed];
mp[sum]++;
```

First, count using prefix sums from **earlier positions**. Then record the current prefix sum for future positions.

This keeps the current prefix from being treated as its own earlier prefix. It also correctly counts non-empty subarrays.

## 12. What If the Needed Sum Is Not in the Map?

With `unordered_map`, `mp[needed]` inserts the key with a default value of zero if it doesn't already exist. Adding zero leaves `count` unchanged.

This is valid and concise for this solution. Note that `operator[]` can insert a missing key; `find()` is an alternative if you want to check without inserting.

## 13. Why Sliding Window Is Not Always Correct Here

A simple sliding window often relies on nonnegative values: when a sum is too large, removing elements from the left reduces it.

But this problem allows negative numbers. For example, `[4, -1]` has a subarray sum of `3`. A sum can increase or decrease when we add a number, so a simple rule like “if the sum is too large, move the left pointer” is not reliable.

Prefix sums plus a frequency hashmap work with positive numbers, negative numbers, and zeros.

## 14. Time and Space Complexity

- **Time:** O(n) on average. Each element requires a constant number of expected-time hashmap operations.
- **Space:** O(n) in the worst case for the prefix-sum hashmap.

Here, `n` is the number of elements in `nums`.

## 15. Edge Cases

- **One element equals `k`:** `nums = [3], k = 3` → answer `1`.
- **No matching subarray:** `nums = [1, 2], k = 10` → answer `0`.
- **Negative numbers:** `nums = [4, -1], k = 3` → answer `1`.
- **Zeros and repeated prefix sums:** `nums = [0, 0], k = 0` → answer `3` because `[0]` at each position and `[0, 0]` are valid.
- **Multiple occurrences of the needed prefix:** add the entire frequency, not just `1`.

## 16. Interview Memory Trick

Remember the four actions:

```text
1. Update running sum
2. Find needed = sum - k
3. Add mp[needed] to count
4. Record mp[sum]++
```

**Short phrase:** Update → Count → Remember.

Also remember the initialization: `mp[0] = 1`.

## 17. Common Mistakes and Revision Notes

- **Mistake:** Using a simple sliding window despite negative numbers.
  - **Why it's wrong:** A larger sum can later decrease when a negative number is added.
- **Mistake:** Storing only whether a prefix sum exists.
  - **Why it's wrong:** The same prefix sum can appear at multiple earlier positions, producing multiple valid subarrays.
- **Mistake:** Adding only `1` to the answer for a match.
  - **Why it's wrong:** Add `mp[needed]`, the full frequency.
- **Mistake:** Forgetting `mp[0] = 1`.
  - **Why it's wrong:** Subarrays beginning at index 0 may not be counted.
- **Mistake:** Updating `mp[sum]` before checking `mp[sum - k]`.
  - **Why it's risky:** It can count an empty subarray when `k = 0`.

### The discovery process to reuse in future problems

1. Start with a simple brute-force approach.
2. Identify repeated work.
3. Look for a mathematical relationship that removes the repeated work.
4. Rearrange the condition to find what earlier information is needed.
5. Choose a data structure based on the question: here, a hashmap for fast lookup and frequency counting.
6. Verify duplicates, initialization, and edge cases before coding.
