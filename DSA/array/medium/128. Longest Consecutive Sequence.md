# 128. Longest Consecutive Sequence

**LeetCode:** [128. Longest Consecutive Sequence](https://leetcode.com/problems/longest-consecutive-sequence/)  
**Difficulty:** Medium  
**Pattern:** Sorting + counting

## 1. Problem

Given an unsorted integer array `nums`, return the length of the longest sequence of consecutive integers. The consecutive numbers do not need to appear next to each other in the original array.

### Example

**Input**
```cpp
nums = {100, 4, 200, 1, 3, 2};
```

**Output**
```text
4
```

Explanation: The longest consecutive sequence is `{1, 2, 3, 4}`, which has length 4.

## 2. Approach: Sort and Count

1. If the array is empty, return `0`.
2. Sort the array in ascending order.
3. Start `count = 1` for the current consecutive sequence and `ans = 0` for the best length found.
4. Compare each element with the next one:
   - If they are equal, skip the duplicate. It should not increase the sequence length or break it.
   - If the next value is exactly one greater, increase `count`.
   - Otherwise, update `ans` with the current `count` and reset `count = 1` for the new sequence.
5. After the loop, update `ans` one final time because the longest sequence may end at the last element.
6. Return `ans`.

## 3. C++ Solution

```cpp
class Solution {
public:
    int longestConsecutive(vector<int>& nums) {
        if (nums.size() == 0) {
            return 0;
        }

        int count = 1;
        int ans = 0;
        sort(nums.begin(), nums.end());

        for (int i = 0; i + 1 < nums.size(); i++) {
            if (nums[i] - nums[i + 1] == 0) {
                continue;
            }

            if (nums[i] - nums[i + 1] == -1) {
                count++;
            } else {
                ans = max(ans, count);
                count = 1;
            }
        }

        ans = max(ans, count);
        return ans;
    }
};
```

## 4. Code Explanation

| Code | Meaning |
|---|---|
| `if (nums.size() == 0) return 0;` | An empty array has no consecutive sequence. |
| `count = 1` | A sequence containing one distinct number has length 1. |
| `ans = 0` | Stores the longest sequence length found so far. |
| `sort(nums.begin(), nums.end())` | Places values in ascending order so consecutive values become adjacent. |
| `i + 1 < nums.size()` | Ensures `nums[i + 1]` stays within the array bounds. |
| `nums[i] - nums[i + 1] == 0` | The two values are duplicates; skip without changing `count`. |
| `nums[i] - nums[i + 1] == -1` | The next value is exactly one greater, so extend the current sequence. |
| `ans = max(ans, count)` | Saves the larger of the best length so far and the current sequence length. |
| `count = 1` | Starts a new sequence at the next distinct number after a gap. |
| Final `ans = max(ans, count)` | Checks the last sequence, which might end when the loop ends rather than at a gap. |

## 5. Dry Run

**Input:** `{1, 2, 6, 7, 8}`

The array is already sorted. Initially, `count = 1` and `ans = 0`.

| Pair | Difference `nums[i] - nums[i+1]` | Action | `count` | `ans` |
|---|---:|---|---:|---:|
| `(1, 2)` | `-1` | Consecutive; increment count | 2 | 0 |
| `(2, 6)` | `-4` | Save count, then reset | 1 | 2 |
| `(6, 7)` | `-1` | Consecutive; increment count | 2 | 2 |
| `(7, 8)` | `-1` | Consecutive; increment count | 3 | 2 |
| End of loop | — | `ans = max(2, 3)` | 3 | 3 |

**Output:** `3`, because `{6, 7, 8}` is the longest consecutive sequence.

## 6. Important Edge Cases

- **Empty array:** `{}` → `0`.
- **Single element:** `{5}` → `1`.
- **Duplicates:** `{1, 2, 2, 3}` → `3`; duplicates do not increase the count.
- **A gap before the longest sequence:** `{1, 2, 6, 7, 8}` → `3`; do not return as soon as a gap is found.
- **Longest sequence at the end:** the final `ans = max(ans, count)` is necessary to record it.

## 7. Key Insight

Keep two counts:

- `count` tracks the current consecutive sequence.
- `ans` tracks the longest sequence found.

When there is a gap, update `ans` and reset `count`. After the loop, update `ans` one last time because the final sequence may be the longest.

## 8. Complexity

- **Time:** `O(n log n)` for sorting, followed by an `O(n)` scan; overall `O(n log n)`.
- **Auxiliary space:** sorting uses implementation-dependent stack space; the counting variables use `O(1)` extra space.

**Note:** This is the sorting-based solution. The optimal expected `O(n)` approach uses an unordered set, but sorting is a useful way to learn the sequence-counting logic first.
